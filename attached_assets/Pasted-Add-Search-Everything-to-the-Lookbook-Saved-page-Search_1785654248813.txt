Add Search Everything to the Lookbook/Saved page

Search bar Add one rounded search bar on the Saved page, directly below the page subtitle and above the first card. Include a magnifying-glass icon on the left and a clear × button when text is entered. Placeholder: "Search…". Preserve all existing design.

What to search Search all locally stored text on each item: name, brand, color, category, notes, size, season, occasion, price, date. Also search group/lookbook names and notes. Also search two auto-generated fields per item: visionLabels (color and object labels extracted from the photo) and visionText (text detected inside the photo). Score each field separately — name and brand rank highest, vision fields rank lowest. Deduplicate results.

Color extraction from photos (web) On web, extract dominant colors from each photo using a 48×48 canvas. Detect the background color by sampling 4×4 patches from each corner, then exclude pixels that match the background so studio backgrounds don't pollute the results. Map surviving pixels to color names: black (brightness < 80), dark grey (< 110), grey (< 175), light grey (< 225), white, beige, tan, brown, red, orange, yellow, green, teal, blue, purple, pink. A color must cover at least 10% of foreground pixels to be included.

Native iOS Vision (Capacitor apps) Create a Swift Capacitor plugin with VNClassifyImageRequest (confidence threshold 0.3) and VNRecognizeTextRequest (accurate mode). Run both requests synchronously on a background queue. Return labels and recognized text to the web layer. Fall back silently to empty arrays on any error. Register the plugin with a standard ObjC .m bridge file and add both files to the Xcode build phases.

Background indexer Store visionLabels: string[], visionText: string[], and visionVersion: number on each item (safe DB migration, default empty). On app start, find all items that need indexing and process them one at a time with a 350ms delay between each so the UI stays responsive. Show a non-blocking "Preparing photo search…" toast while this runs. Queue newly added or updated photos for immediate analysis without waiting for next launch. Version scheme: 0 = unanalyzed, 1 = iOS Vision correct, 4 = current web canvas correct, 5 = web analyzed but no labels found (don't retry). Re-run anything below version 4 on web to pick up threshold improvements.

Search results layout While a query is active, replace the normal page content with results directly below the search bar (scroll the page to the top the instant the user starts typing). Show two sections: individual items first (thumbnail + name + category), saved groups second (3-thumbnail row + group name). A group matches if its name, notes, or any item inside it matches. Tapping an item opens its existing details sheet. Tapping a group opens the group. Clearing search restores the normal page.

Context-aware buttons on the item details sheet The details sheet is opened from multiple places. Add a showAddToLookbook boolean prop. Pass it as true only from search results and the favorites page — never from the main wardrobe. When true: show an "Add to Lookbook" button (opens a picker sheet listing all saved groups with 3-thumbnail previews and a filled checkmark on groups that already contain this item; tapping adds or removes). When false: show the "Clean Up Photo" button instead. Either way, "Wearing Today" always shows. This keeps every context to exactly 2 action buttons.

Safeguards Everything offline — no external APIs, no cloud AI. Non-destructive DB migration. If Vision fails, text search still works. Don't change any unrelated feature.
